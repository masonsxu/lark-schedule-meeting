# lark-schedule-meeting

飞书会议室预约台：按循环规则（不循环 / 每天 / 每周 / 每月 / 每季度）自动预约会议室。公司环境会议室最早可提前 30 天预约，本程序在预约窗口开放的第一时间以固定会议室 ID 定时预约。

- 后端：Go（标准库 + modernc.org/sqlite，无 CGO）
- 前端：Vue 3 + TypeScript + Vite（pnpm workspace）
- 飞书调用：通过本地已授权的 [lark-cli](https://github.com/larksuite/cli) 子进程完成，无需自建应用凭证

## 功能

- **循环规则**：配置首次目标日期 + 循环类型（单选），目标日期依次推进；不循环 = 只预约一次，预约完成（无论成败）规则自动关闭
- **定时预约**：预约发起日 = 目标日期 − 提前天数（默认 30 天）；到"预约开始时刻"后发起预约，10 分钟窗口内每分钟尝试一次，避免高频调用触发风控
- **固定会议室 ID**：按优先级列表依次以 omm_ ID 直传创建日程，成败由飞书 API 判定，不依赖可用性查询（实测飞书检索接口返回的会议室列表不全）
- **跳过周六日**：默认开启，目标日期落在周末时不预约
- **终态记录**：每次预约写入 SQLite（booked / occupied / failed），后续循环自动跳过已处理日期；检测到同名日程已存在时记录并跳过，防止重复预约
- **会议室名录**：手动录入 / 按时间检索自动入库 / 预约成功回写，ID 高亮一键复制，一次录入长期复用
- **Web 控制台**：规则管理、预约会话实时刻度条、预约记录、引擎日志

## 快速开始

前置条件：

- Go 1.26+、Node.js 20+、pnpm 9+
- lark-cli 已安装并完成授权（`lark-cli auth login`，需 `calendar` 相关 scope）

```bash
# 构建前端
pnpm install
pnpm build:web

# 启动服务（默认监听 0.0.0.0:8787，数据存于 ./data/lsm.db）
go run ./server/cmd/lsm
# 或
go build -o server/bin/lsm ./server/cmd/lsm && ./server/bin/lsm
```

浏览器打开 http://127.0.0.1:8787 。开发模式：

```bash
pnpm dev:server   # 后端 :8787
pnpm dev:web      # 前端 :5173，/api 代理到 8787
```

## 规则模型

| 字段 | 说明 |
| --- | --- |
| 会议主题 | 写入日程标题 |
| 首次目标日期 | 第一次要预约的会议日期（YYYY-MM-DD） |
| 循环规则 | 不循环（once）/ 每天 / 每周 / 每月 / 每季度，单选；每周=同星期，每月/每季度=同日 |
| 会议开始/结束 | 目标日期当天的会议时间 |
| 预约开始时刻 | 预约发起日当天触发预约的时刻（如公司 00:00 放号就填 00:00） |
| 提前天数 | 预约发起日 = 目标日期 − 提前天数，默认 30 |
| 会议室优先级 | 固定 omm_ ID 列表，依次尝试，第一个成功即结束 |
| 跳过周六日 | 默认开启 |
| allowNoRoom | 会议室全部失败时仍创建无房会议（验证链路用） |

示例：首次目标 2026-11-19、每周循环、提前 30 天、预约开始 08:00 —— 则 2026-10-20 08:00 预约 11-19、2026-10-27 08:00 预约 11-26，依次类推；某日已约/已处理则自动跳过。

## 工作原理

1. 调度器每 15 秒扫描一次：对每条启用规则计算"今天 + 提前天数"是否为有效目标日期（循环匹配 + 周末判断）
2. 命中且到达预约开始时刻、无终态记录、无运行中会话时启动预约会话
3. 会话先预检主日历是否已有同名日程覆盖该时间块（有则记录并跳过），随后每分钟按优先级直传固定会议室 ID 创建日程
4. 成功 → 记录 booked；窗口结束仍无成功 → occupied（房间被占）或 failed（接口异常）；once 规则在终态后自动关闭
5. 全部数据持久化在 `data/lsm.db`（SQLite：rules / records / attempts / rooms）

## HTTP API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | /api/rules | 规则列表 / 创建 |
| GET/PUT/DELETE | /api/rules/{id} | 规则详情 / 更新 / 删除 |
| POST | /api/rules/{id}/run | 手动触发（可指定 date、maxAttempts、intervalSeconds、force） |
| GET | /api/records、/api/attempts、/api/sessions | 记录 / 日志 / 会话快照 |
| DELETE | /api/records/{id}?deleteEvent=true | 删记录并撤销飞书日程 |
| GET/POST/DELETE | /api/rooms（/{id}） | 会议室名录 |
| POST | /api/rooms/available | 按时间块检索可用会议室（结果自动入名录） |

## 已知限制

- 飞书 `search_event` 接口不索引约 30 天外的远期日程，重复检测依赖本地 SQLite 记录为主
- 按月/每季度循环使用"同日"语义，月末日期会归一化（如 1月31日 + 1月 = 3月3日，与 Go/前端一致）
- 按时间检索会议室的接口返回列表可能不全（日历上空闲的会议室也可能不出现），名录以手动录入的固定 ID 为准
- 时区按服务配置（默认 Asia/Shanghai）解释所有日期时间
